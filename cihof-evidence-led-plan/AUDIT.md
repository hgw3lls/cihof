current state, so it comes first.

## 1.3 The material for the missing layer is already in the record

This is the finding that reorders the plan.

`inductedBy` is populated for **111/111** people with 95 distinct inductors,
while `public/data/relationships.json` is `[]`. Of those values, **24** string-
match another inductee's name and **87** name someone outside the collection.

Those 24 are **not** relationships. This project forbids identity inference from
a name, and rightly. What the number measures is the **size of a review queue**:
24 candidate `inducted_by` links between two people already in the collection,
plus 87 candidate links to an external person, each already carrying a source in
the legacy record. That is a bounded, one-pass editorial task with a concrete
finish line — not an authoring project.

The same holds for `storyHighlights`: 444 sentences exist, and 0 story beats
publish.

**The gap is a migration-and-review pipeline that was never built.** CE-01
designed the destination contracts correctly and enforces them correctly; the
road to them does not exist.

## 1.4 Derived text is presented as source text

**Severity: medium. Touches P06 ("Source fidelity … authored text labeled").**

Three fields shown to visitors are pipeline-generated, not authored, and are not
labelled as such:

- **`documentedContextLine`** reads `Class of 2010 honoree connected to Serbian.
  Inducted by Dick Russ.` The pattern `connected to <Demonym>.` — a bare
  demonym used as a noun — occurs in **88/111** records. This is a visible copy
  defect in shipped content.
- **`honoredForSummary`** is a template: `Contributions to <a>, <b>, and <c>
  within <Demonym> heritage communities and to Greater Cleveland's multicultural
  civic life.` It is 0/111 verbatim from `bioText`. The exhibit renders it as the
  person's contribution line via `publishedContribution`.
- **`storyHighlights`** is verbatim `bioText` for **74/111** people and altered
  for the other **37**. A field with inconsistent provenance across the
  collection cannot be cited as source text, and 37 records have had their
  wording changed by something other than an editor.

None of this is dishonest by intent, and the pipeline is transparent about its
sources internally. But the visitor cannot tell the biography from the template,
and P06 requires that they can.

## 1.5 Rights and media

Portraits: 111/111 `imageRightsStatus: approved`, and `validate:kiosk` reports
111/111 wall-ready and kiosk-ready with 0 strict failures. Portrait-and-text
release is not blocked.

Film: 93 holdings, 0 kiosk-ready, 0 public-web-ready. `validate:media-clearance`
fails with 93 strict failures, which is the correct and expected state. The
public artifact correctly contains no film payloads and no pending metadata.

Galleries: 65 people have more than one approved image and there is no gallery
surface in the exhibit. This is approved content that is built, shipped and
unreachable.

# Part 2 — What the code does

## 2.1 The publication boundary is build-time only, and a persistent runtime path goes around it

**Severity: high. Touches P01, P03, P05, P08.**

`loadRuntimeDataBundle()` (`src/data/runtimeDataBundle.ts:34`) reads a
localStorage override **before** the served artifact:

```ts
const override = readRuntimeDataBundleOverride();
if (override) return override;
```

The override's only validation is `normalizeRuntimeDataBundle`, which accepts
any object with an `inductees` array (`:101-104`). No schema check, no revision
check, no publication rules re-applied.

- It **persists**. `clearRuntimeDataBundleOverride` has one caller,
  `AdminDataPanel.tsx:126`. Start Over, idle reset and browser restart all leave
  it in place.
- It is **invisible**. `hasRuntimeDataBundleOverride` has no caller anywhere in
  `src/` outside the admin panel.
- Its gate is **browser storage**. `readAdminSession` is
  `sessionStorage['cihof.admin-data.session.v1'] === '1'`; `readAdminPasscode`
  prefers `localStorage['cihof.admin-passcode.v1']` over the bundled value.

The staff import feature should exist. The finding is the boundary around it:
on an unattended terminal the result outranks the reviewed artifact, survives
every reset the product offers, and nothing revalidates or surfaces it. P08 —
withdrawal — cannot hold while this is true.

## 2.2 `contentRevision` is generated and never read

**Severity: high. Touches P08, P09, O04, O05.**

`grep -rn "contentRevision" src/` returns nothing. CE-01's deterministic
revision is write-only metadata, so caches are not keyed to it, there is nothing
to hang a revocation policy on, the override in 2.1 cannot be checked against
it, and staff cannot be shown which content a device is running.

## 2.3 The runtime bundle's local fallback is unreachable code

**Severity: high. Touches O02, O03, O06.**

`localDataCache.ts` refuses entries over `maxEntryBytes = 1_500_000`.

```
dist/data/cihof-runtime-data.json   3,150,834 bytes
dist/data/inductees.json            1,281,337 bytes
```

The write at `runtimeDataBundle.ts:48` therefore **always** takes the oversize
branch, and the matching read at `:55` can never return anything. The primary
data path has no working offline fallback, and the failure logs at `debug`.
`inductees.json` sits at 85% of the cap, so the legacy fallback is one content
addition away from the same fate. No test or validator covers either.

## 2.4 The service worker contradicts its requirements

**Severity: high. Touches O01–O07.**

`public/sw.js` is 87 lines of opportunistic caching.

| Case | Required | Actual |
|---|---|---|
| O05 | New release must not hijack a session in progress | `install` → `self.skipWaiting()`, `activate` → `self.clients.claim()` (`:8,18`). Exactly inverted. |
| O04 | Last working release stays available | `activate` deletes every prior `cihof-runtime-` cache (`:13-16`). Nothing survives to roll back to. |
| O01–O03 | Manifest, checksums, restart offline incl. unvisited deep link | No precache, no manifest. An unvisited person link fails offline. |
| O06 | A cache-write failure must not blank a successful response | `networkFirst` awaits `cache.put` **inside** its `try` (`:57-59`); a quota failure is caught, falls through to `cache.match`, and rethrows if nothing is cached — discarding a response that already arrived. Live defect. |

`serviceWorkerRegistration.ts` registers and does nothing else: no
`updatefound`, no waiting-worker coordination, no `update()`. The "agreed
activation point" has no implementation to extend.

## 2.5 `validate:offline` does not validate offline operation

**Severity: medium, and it is an evidence-integrity problem.**

`scripts/validate-offline-package.js` checks that local asset references resolve
inside `dist/`. It contains no occurrence of `sw.js`, `serviceWorker`,
`precache`, `checksum` or `integrity`, and never loads anything with the network
off. It prints `CIHOF offline package validation passed`, and MG and CE
completion records cite that line as offline evidence. Given 2.3 and 2.4, the
artifact it passes has a dead fallback and a worker that precaches nothing.

## 2.6 The admin surface ships in the public artifact

**Severity: medium. Touches P05.**

`src/features/admin/` contains no `buildTarget` reference. `grep -c "Unlock"
dist/assets/index-*.js` returns 1 — the panel is in the deployed public bundle,
opened by `?admin=1` or a five-tap brand gesture.

`.github/workflows/pages.yml` runs `npm run build:public` with no
`VITE_CIHOF_ADMIN_PASSCODE`, so the public unlock form correctly refuses. But
`VITE_*` is substituted at compile time: in a build that *does* set it, the
passcode is a literal in the shipped JavaScript. I verified this — the string
appears twice in a bundle built with it set. And the panel reaches 2.1.

## 2.7 The regression suite went dark and nothing noticed

**Severity: high, as a process finding.**

`npm run test:kiosk` exited 1 having collected **zero** tests, because a
Vite-`define`-dependent import (`buildInfo` → `__CIHOF_BUILD_INFO__`) reached a
Node-context spec. Every visitor test was silent, and the command's output was
indistinguishable from an ordinary failure.

Nothing in the repository asserts that the suite collected a plausible number of
tests. A suite that cannot run looks exactly like a suite with nothing to say.
This is the single cheapest thing to fix in the whole audit and it protects
everything else.

Two genuine regressions were live behind that silence (Links constellation
destroyed by the shared query; a record opened over a film discarding the film).
Both are fixed and verified; both were found by reading, not by the suite.

## 2.8 Retained legacy code is inert but has no stated exit

**Severity: low.**

~7,000 lines across `living-hall/`, `App.tsx`, `inductee-detail/` and
`traceModel.ts` are kept as rollback code. They are correctly tree-shaken:
`LivingHall`, `CityQuestion`, `InducteeDetail`, `commandSearch`, `traceModel`
and `connectionGraph` each appear **0** times in the public bundle. Visitors pay
nothing. Every typecheck, refactor and reviewer does. O11 describes an
artifact-level rollback, not a different React tree, and no document describes a
scenario in which this code is what gets restored.

## 2.9 What is in good shape

Stated because an audit that only lists problems is not an audit.

- **Build-time publication filtering is sound.** CE-01's selectors are pure,
  shared between the build and the UI, and verified: the new entity and
  relationship gates retain exactly the rows the previous rules retained on
  current data, and the contract suite passes 4/4.
- **Referential integrity is enforced at build time** and throws.
- **The active visitor surface is small and legible**: ~2,000 lines across nine
  files.
- **Accessibility has real coverage**, including `@axe-core/playwright`, modal
  and focus-return tests, 200% text, narrow reflow and reduced motion.
- **Session and media lifecycle hygiene is careful** — timers cleared, listeners
  removed, media stopped on reset.
- **The kiosk/public/portal split works** and staff-only data is correctly
  excluded from visitor targets.

   surfaces are built on top of it.** (1.4)
4. **The review pipeline is the critical path to every interpretive surface.**
   (1.3) Six surfaces built ahead of it render empty.
