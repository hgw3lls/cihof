## Changes and rationale

### A run that collects nothing now fails as itself

Two layers, because one is not enough.

`tests/reporters/collected-count.ts` fails a run that collected fewer tests than
the maintained minimum, and prints the collected count on every run so records
can cite it.

`scripts/assert-test-count.mjs`, wired into `test:kiosk` and `test:portal`,
repeats the assertion at the npm entry point. This exists because a CLI
`--reporter` flag **replaces** the config's reporters and silently removes the
first layer. That is not hypothetical: the first verification run of this stage
passed `--reporter=line`, lost the guard, and reported a clean pass on a run
that collected 10 of 82 tests.

`tests/minimum-tests.json` is the single source for both (82 visitor, 2 portal),
read with `readFileSync` rather than a JSON import, because a plain JSON module
import requires an import attribute under this Node and fails to load the
Playwright config.

### The flake was a focus defect, not a test defect

`tests/links-relationships.spec.ts:221` failed intermittently in full-suite runs
and passed in isolation. The cause is in the product: the connection-list toggle
scheduled a `requestAnimationFrame` that focused the list heading
**unconditionally**, so anything that moved focus in the same frame was
overridden. Preceding specs shifted the timing, which is what made it look
order-dependent.

This is also a real keyboard trap. A visitor who opens the connection list and
immediately tabs is pulled back to the heading. The stage prompt said to
diagnose the shared state rather than add a retry, and a retry here would have
concealed an accessibility defect in a project whose MG-06 accessibility
sign-off is still open.

`focusListTitleUnlessMoved` now moves focus into the list only if focus is still
where the click left it.

### CI

`.github/workflows/pages.yml` builds and deploys to the public site on every
push to `main` and runs **no tests at all**. This stage records that and changes
nothing: a failing gate blocks publishing, which is the repository owner's call.

Recommendation, in order of cost: add `npm run test:count` to the workflow — two
seconds, no browsers, and it would have caught the zero-collection state
outright — and then a full visitor-suite job if the runtime budget allows.
