# Handover checklist

To work through with the museum on handover day, with the display and the
staff computer side by side. Tick each line only when it has been done and
seen working, by the person named. The staff guide (`STAFF-GUIDE.md`) and
the staff portal walkthrough (`training/staff-portal.md`) have the detail.

**Who takes it on**

| Role | Name | Contact |
| --- | --- | --- |
| Looks after the content (staff portal) | | |
| Administrator of the display PC | | |
| Developer, for what still needs one | | |

---

## 1. The display

- [ ] *CIHOF Exhibit* installed on the display PC, and starting at sign-in (staff guide 2.1, 2.2)
- [ ] The admin passcode set by the museum, not by the developer, and written down where the museum keeps passwords (2.3)
- [ ] The films folder chosen in the admin panel, and every film playing (**Films** says how many are found)
- [ ] The nightly restart time set (**Settings › Daily restart**)
- [ ] The attract screen chosen (**Attract screen and colours**)
- [ ] Recorded: the app's version and release (admin panel, **This display**): __________

## 2. The staff computer

- [ ] *CIHOF Staff Portal* installed on the staff computer
- [ ] On the museum network, and able to reach the display: in the admin panel, **Staff connection › Open a staff connection**; in the portal, **Connect to a display** with the address and code shown. It opens what the display shows.
- [ ] If Windows asked, *CIHOF Exhibit* allowed through the display's firewall, and the museum's IT has noted port 5190 between the staff computer and the display
- [ ] The same done once with a USB stick instead: **Content › Export current content…** on the display, **File › Open a display's content…** in the portal

## 3. A first change, end to end

Done by the person who will look after the content, with the developer watching.

- [ ] A small, real correction made in the portal's studio: the person opened on the exhibit, **Edit**, their name or biography touched, changed and saved, and seen on the exhibit
- [ ] **Undo** tried, and the change saved again
- [ ] The change approved (the bar's *waiting for approval*), by a second person if the museum prefers
- [ ] A display update made (**The display › Make a display update**), sent to the display (or carried on a stick), and **Apply at the next reset**
- [ ] The change seen on the display after it returns to its attract screen
- [ ] **Content › Versions kept › Show this version** on the previous version, then back to the new one: going back seen working
- [ ] An update made from an older version, and the display's warning about it seen (start again from what the display shows)

## 4. The yearly class

- [ ] The new-inductee form walked through (**+ Inductee** in the studio), and where the museum keeps the Hall of Fame's record of each induction to fill it from
- [ ] Adding a film walked through (a person's **Watch the film** in the studio, then **Add a film…**): the MP4, the captions, the checks
- [ ] **To review** and **All items** shown: what the research holds for somebody to decide, and the card-by-card screens for working through many

## 5. Backups

- [ ] The display's content exported after the first update, and stored with the backups (staff guide 8)
- [ ] The films folder copied to two external drives, one kept elsewhere
- [ ] The current installers of both apps stored with them
- [ ] Everyone agrees: installers, exports, updates and films are for the display only, never on a website or a public share
