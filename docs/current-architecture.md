# Current Architecture

Updated: September 19, 2026.

## Public Exhibit

The public visitor experience is a single persistent archive exhibit. Its active entry is:

- `index.html`
- `src/app/main.tsx`
- `src/features/archive-exhibit/ArchiveExhibit.tsx`

The three public scenes are `PEOPLE`, `LINKS`, and `YEARS`. A selected inductee remains in focus while the visitor moves between scenes, and the URL preserves both the scene and selected person.

`PEOPLE` is the complete portrait index. `LINKS` presents a Cleveland constellation built only from documented archive relationships and induction-class connections. `YEARS` is a horizontal film and class chronology. Each scene can open the same full inductee record without becoming a separate application.

Legacy visitor routes map into this model:

- people, search, explore, and home -> `PEOPLE`
- connections, journeys, world, routes, places, and region map -> `LINKS`
- time and timeline -> `YEARS`
- `person=...` -> the persistent selected inductee

## Visitor Record

The focused rail provides concise interpretive context and a route to the full record. The full record contains biography, induction notes, documented heritage and community fields, the reason the person is honored, and a QR handoff for continued reading.

Film assets appear publicly only when rights, local media, poster, captions, and transcript requirements all pass `publicReadyFilm()` in `src/features/archive-exhibit/archiveModel.ts`. Preserved films that are not yet cleared remain visible as archive holdings but cannot be played.

## Staff Portal

The staff portal is a separate app:

- `portal.html`
- `src/app/portal-main.tsx`
- `src/app/PortalApp.tsx`
- `src/features/review-dashboard/ReviewDashboardView.tsx`

The portal handles:

- curation review
- source-derived draft queues
- profile data edits
- relationship review
- media review
- runner-backed apply/build/validation flows

The public visitor app does not import the staff review dashboard.

## Hidden Visitor Admin

The public app has a hidden password-protected admin panel:

- `src/features/admin/AdminDataPanel.tsx`

It is for operational kiosk tasks only:

- export runtime data
- import browser-local runtime data override
- reset to built-in runtime data
- tune kiosk/app settings
- change local admin password
- change admin hotkey
- export diagnostics

Profile curation belongs in the separate portal, not in hidden visitor admin.

## Runtime Data And Offline Operation

The preferred public runtime source is:

```text
public/data/cihof-runtime-data.json
```

It is generated by:

```sh
npm run prepare:data
```

Runtime loaders retain split-file fallbacks for compatibility. The production service worker owns offline delivery of the runtime bundle and local media. Browser `localStorage` is a small fallback cache only; oversized payloads are intentionally skipped so duplicate bundle data cannot exhaust kiosk storage. Imported staff overrides remain separate and explicit.

## Validation

Important validation commands:

```sh
npm run typecheck
npm run validate:entities
npm run validate:offline
npm run build:public
npm run test:kiosk
```

Run the kiosk suite against the built preview when service-worker behavior is under test; service workers are intentionally disabled by Vite during development.
