# Current Architecture

Updated: August 25, 2026.

## Public App

The public visitor app is one persistent Hall surface.

The conceptual state model is:

```ts
type HallLens = 'portraits' | 'traces' | 'legacies';
type HallFocus = { personId: string } | null;
```

`HallLens` changes arrangement. `HallFocus` changes emphasis. Neither should replace the Hall with a separate visitor page.

Active public visitor entry:

- `index.html`
- `src/app/main.tsx`
- `src/app/App.tsx`
- `src/features/hall-surface/HallSurface.tsx`
- `src/features/living-hall/LivingHallView.tsx`

The public navigation exposes only:

- `PORTRAITS`
- `TRACES`
- `LEGACIES`

## Persistent Portrait Frames

The persistent visual object is the keyed portrait frame.

`src/components/PortraitFrame.tsx` renders the frame primitive and supports the same component moving through these states:

- `standard`
- `focus`
- `trace`
- `legacy`

Lens changes should primarily change frame position, size, emphasis, grouping, contextual labels, and line visibility.

## Focused Person

A person is a focused condition of a portrait frame, not a visitor destination.

Focused actions remain anchored to the Hall:

- `LIFE + WORK`
- `WATCH INDUCTION`
- `TAKE IT WITH YOU`

Reusable detail/media pieces still live under `src/features/inductee-detail/`, but visitor usage is anchored by `LivingHallView`.

## TRACES

TRACES replaces the old public roles of Connections, Follow a Thread, World, Routes, Places, and Region Map.

It uses:

- generated entity relationships
- curated relationship records when present
- story-lens concepts
- guarded geography references
- Cleveland trace line language

Safeguards:

- do not invent relationships
- do not infer migration
- do not imply every person is an immigrant
- do not draw directional migration arrows unless direction is explicitly documented

## LEGACIES

LEGACIES replaces the old public Time/Timeline screen.

The portrait collection itself becomes the timeline. Frames are sorted by real `classYear`, grouped by induction class, and moved through a horizontal register with drag/swipe and accessible chronology controls.

## Staff Portal

The staff portal is a separate app:

- `portal.html`
- `src/app/portal-main.tsx`
- `src/app/PortalApp.tsx`
- `src/features/review-dashboard/ReviewDashboardView.tsx`

The portal handles:

- curation review
- source-derived draft queues
- profile data edits
- relationship review
- media review
- runner-backed apply/build/validation flows

The public visitor app does not import the staff review dashboard.

## Hidden Visitor Admin

The public app has a hidden password-protected admin panel:

- `src/features/admin/AdminDataPanel.tsx`

It is for operational kiosk tasks only:

- export runtime data
- import browser-local runtime data override
- reset to built-in runtime data
- tune kiosk/app settings
- change local admin password
- change admin hotkey
- export diagnostics

Profile curation belongs in the separate portal, not in hidden visitor admin.

## Runtime Data

The preferred public runtime source is:

```text
public/data/cihof-runtime-data.json
```

It is generated by:

```sh
npm run prepare:data
```

Runtime loaders still retain fallback paths for older split data files. Staff/source-review queues and standards exports are emitted as separate files rather than embedded in the kiosk runtime bundle.

## Compatibility URLs

Legacy public URLs are preserved by mapping them into Hall state:

- old people/search/explore/home views -> `PORTRAITS`
- old connections/journeys/world/routes/places/region-map views -> `TRACES`
- old time/timeline views -> `LEGACIES`
- `person=...` -> `HallFocus`

Staff/review URLs are separate and should not be remapped into public Hall lenses.
